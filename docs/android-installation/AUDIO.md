# Embedded Android audio — 7 October 2026

Start the device and use **Mute / unmute** to enable or disable embedded controller audio. Audio starts off. If the browser requests activation, click the Android viewport; retry the toggle if activation times out. Guest volume controls still adjust Android volume. Stop, reconnect and remote display loss stop audio. No host microphone capture or injection is added.

The existing authenticated EmulatorController streamAudio RPC supplies 48 kHz, stereo, signed 16-bit little-endian PCM. Audio has its own token-authenticated loopback WebSocket, separate from display/input. One packet awaits an AudioWorklet receipt; a stalled receiver closes after 500 ms. Packets are limited to 19,200 bytes. The renderer uses a preallocated 19,200-byte ring (100 ms), transfers incoming buffers instead of copying them on the browser main thread, drops oldest samples on overflow and emits silence on underrun. No audio encoder, codec library or dependency is added. Raw sample traffic is approximately 192 kB/s at full rate, excluding transport overhead; audio requests and the context cease when disabled.

The worklet renders on the browser audio thread. Stop releases the gRPC stream, WebSocket callbacks, worklet port/node and AudioContext. Concurrent enable requests are superseded before allocation. Native host output is disabled with -no-audio for embedded controller sessions to avoid duplicate playback; the real installed emulator still supplies the PCM RPC with that flag. Standalone mode remains separate. The existing WebRTC path retains its media-track mute handling.

Passed: 116 .NET tests, 30 browser/input tests, 10 gateway tests; Release build; standard and composition host smoke checks in audio-smoke. Audio coverage includes stereo sample values, silence, bounded overflow, concurrent enable, mute/reconnect cleanup, token rejection, exclusive audio ownership, packet format/size rejection, consumer timeout and shutdown of an active stream.

Real Android evidence: embedded-audio-final.json records a running audio renderer with 435 packets, 858,360 bytes and nonzero rendered samples (peak 0.0010986328125). No discarded samples or underrun samples were reported during this short run. Display decoded 182 frames over approximately 17 seconds, including continued updates during audio playback. Graceful device shutdown passed. audio-resource-check.json records no remaining processes among the observed app/emulator/gateway/browser IDs after shutdown. The preceding embedded-audio.json run also streamed successfully. The real reports predate the subsequent small concurrent-start fix, verified by its regression test.

Performance: the short evidence run has increasing frame throughput as Android warms up, so its before/after audio windows are not a controlled performance comparison. It does not prove zero CPU impact, zero audio/video drift or representative gaming performance. Physical speaker/headphone output, subjective quality, end-to-end latency/synchronization, prolonged playback and repeated-device-cycle resource release remain unverified. The report's audioVerified=false deliberately preserves this physical-listening gate; packet delivery and rendered nonzero samples are separately evidenced. The newTouchReceived check failed in these audio runs; earlier touch evidence does not resolve this run's diagnostic-tap failure.

No SDK licences, authentication allowlists, Android disks, profile settings schema or historical release packages were altered. Dependency inventory is updated in this directory; use the rebuilt Release application. Shared ADB server ownership remains an inherited open cleanup gate.

Protocol reference: [official EmulatorController definition](https://android.googlesource.com/platform/tools/base/+/e50f3a6a1809ad5b2040876123bf3bf04c2db08e/emulator/proto/emulator_controller.proto). Playback activation follows [Chrome's Web Audio autoplay policy](https://developer.chrome.com/blog/autoplay).
