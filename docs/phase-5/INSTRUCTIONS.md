# Phase 5 — expansion steps (deferred)

1. Read the canonical plan, Phase 0–4 results and services/adapters. Close or explicitly document outstanding runtime/media/input/save/performance/release gates before extending a provisional transport. Preserve measured evidence and existing data.
2. Choose one expansion from demonstrated needs and obtain its scope: APK library, device profiles/consistent backups, separate memory instrumentation, remote access or iOS feasibility. Do not implement all expansions together or infer authorization from this handoff.
3. For an APK library, extend the shared importer and metadata model, add a database only when browsing/query needs justify it, migrate the single selection non-destructively and retain per-package Android data. Keep standalone/split-format support explicit; test signature/version/error retention.
4. For profiles, define identity/configuration and resource limits, isolated storage and session ownership. Keep one active device until concurrent-device scope and performance are separately approved and measured. Do not derive disk identity from emulator serials.
5. For backups/checkpoints, provide explicit operations with consistent device shutdown, verification, cancellation and restore compatibility checks. Never copy running virtual disks as a consistent backup. Preserve originals and explain snapshot/image dependencies and online-state limitations.
6. For memory testing, create a separate instrumented device/build profile for the user's own testing. Google Play images restrict elevated privileges. Define observability and permission boundaries; do not modify the normal Play device or promise to hide instrumentation.
7. For remote access, write a separate authenticated encrypted session/control design, authorization and credential lifecycle, network exposure and input ownership rules. Keep the current loopback boundary until that design is approved and tested.
8. For iOS, evaluate official tooling, host requirements, app/signing constraints and feasible device integrations in a separate report. Do not promise APK execution or reuse Android runtime assumptions.
9. Implement only the selected scope using existing themes/adapters and bounded pipelines. Add meaningful migration, recovery, data-retention and performance tests, plus exact hardware steps where unavailable.
10. Update the plan, runtime/dependency inventory and release artifacts as needed. Deliver actual passed/failed/unverified results and the next scoped handoff. Retain original recordings, game data and settings; no unrelated features.
