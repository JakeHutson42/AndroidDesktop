# Android Desktop

The rebuilt app now uses the [Graphite design system](design/DESIGN_MATRIX.md): a calm Windows desktop theme, readable Segoe UI text, compact device toolbar, persistent APK sidebar, automation panel and matching Setup/Settings forms. Panels adapt to smaller windows, fullscreen keeps controls reachable, and typography follows Windows accessibility text scaling. See [implementation and validation](design/IMPLEMENTATION.md). Run the rebuilt source or `scripts/Start-LocalAndroidApp.ps1`; historical installers predate this styling overhaul.

C#/.NET 10 WPF application following [the implementation plan](IMPLEMENTATION_PLAN.md), with Corvus palettes and a persistent application-owned Android device.

Phase 2 implementation provides **Open APK** and Explorer drop on the dedicated app card, official APK metadata/compatibility inspection, one persisted selected app, verified unchanged-installed launch, non-destructive update/replacement, launch/relaunch and Back/Home/volume/rotate/mute/fullscreen controls. Selected metadata uses settings schema v2; existing Phase 1 themes, window bounds and setup paths migrate without resetting the device.

Run `dotnet run --project src/AndroidDesktop -c Release`. The shell shows before prerequisite checks finish. Configure missing dependencies in Setup, following [Phase 1 setup steps](phase-1/RUNBOOK.md), then use [Phase 2's runbook](phase-2/RUNBOOK.md). The first successful import starts/connects the app-owned device when necessary. Drop onto the WPF app card, not the native viewport.

[Actual Phase 2 results](phase-2/RESULTS.md): Release build, 56 .NET tests, 10 browser-input tests and both native host smokes pass. **Real Android/game/audio/input/save/performance acceptance remains unverified** because SDK/Java/target APK prerequisites were not supplied. WebRTC is still provisional; source protocols do not certify a released Windows emulator. Follow [Phase 0's hardware measurement steps](phase-0/RUNBOOK.md).

Settings are `%LOCALAPPDATA%/AndroidDesktop/settings.json`; device disks remain in the stable `avd` subdirectory. The app never silently uninstalls, clears Android data or recreates an AVD to solve an import error. A device UUID marker inside its actual `.avd` directory distinguishes device data from a reusable emulator serial. Forced host termination is an explicit option only after failed graceful shutdown.

Phase 3 adds recovery hardening, bounded/redacted support diagnostics, self-contained Windows x64 candidate publishing with an isolated private gateway, an Inno Setup installer, dependency/notices inventory and a Windows CI workflow. The single-device/single-selected-APK scope and Corvus palettes remain.

**Phase 3 acceptance remains open.** No SDK/Java/game was supplied for actual Android media, saves, latency, the two-hour soak or twenty device cycles. [Actual Phase 3 results](phase-3/RESULTS.md) distinguish passing code/package/installer smokes from unverified hardware/clean-PC checks. Use [Hardware and Setup](phase-3/HARDWARE_AND_SETUP.md), [Recovery](phase-3/RECOVERY.md) and [Build](phase-3/BUILD.md). Corvus redistribution and full license review also remain open before public/commercial distribution. Artifacts are unsigned evaluation candidates.

Phase 4 adds the Device page's input automation controls: persistent recordings, separate-copy interrupted recovery, exact replay, pause at released-input boundaries, finite/infinite loops and optional seeded variations. Run parameters and dispatch receipts are saved independently; optional detector notes are user observations. Original recordings remain unchanged. No recording editor, library, backups, instrumentation, remote access or iOS is implemented.

See [Phase 4 results](phase-4/RESULTS.md) and [the local runbook](phase-4/RUNBOOK.md). The Release tests and Windows host smokes pass; real Android replay, release behavior and recording overhead remain unverified. Existing publish/installer artifacts predate Phase 4; run from the rebuilt source for these controls.

Phase 5 adds the agreed **APK library** on Device. Successfully imported standalone APKs are retained in settings schema v3, one entry per device/package. Select an entry and Launch library app, or Locate APK / update when a source moves. Existing selected metadata migrates without deleting Android data. JSON storage reuses the importer and themes; no database or additional device is introduced. With no APKs yet available, the library starts empty. See [Phase 5 results](phase-5/RESULTS.md) and [usage/validation](phase-5/RUNBOOK.md). Run from source; historical installers do not include Phase 5.

Phase 6 adds **device profiles** on Setup. The existing device becomes Default device without moving its data; new profiles have separate Android storage, settings and APK libraries. Stop the current device, Add profile, explicitly Switch, then configure/create its device. Only one device can be active. Schema v4 retains legacy metadata and validated guest RAM/CPU overrides are optional. See [actual results](phase-6/RESULTS.md) and [usage/validation](phase-6/RUNBOOK.md). Real Android isolation/save/performance acceptance remains open. Run the rebuilt source; historical installers do not include Phases 4–6.

Phase 7 adds **device backups, verification, same-device restoration and interrupted recovery** on Setup. Backup/restore require an actual graceful stop in the current session and exclusive ownership. Restores stage/verify first, preserve the original directory and journal disk/metadata commits. Pending restores block startup until recovery succeeds. See [actual results](phase-7/RESULTS.md) and [usage/recovery](phase-7/RUNBOOK.md). Real Android saved-progress/disk consistency remains unverified; source fixtures are not hardware acceptance. Run rebuilt source, since historical installers predate Phases 4–7. Backups may contain account/private data and are not encrypted by this feature.

Local Android 14 Google Play is now installed and configured, with real boot and diagnostic APK launch verified. Run scripts/Start-LocalAndroidApp.ps1, then Start device. Android opens inside the app using the authenticated controller display (up to 15 fps). Mute / unmute toggles optional stereo audio; click the Android viewport if browser playback needs activation. Audio is off initially and stops with the device. The experimental RTC transport remains incompatible. See [installation and actual results](android-installation/RESULTS.md) and [audio checks](android-installation/AUDIO.md).
